# Writers Circle 正式上线前检查清单

这份清单用于本地验收。测试资料必须完全虚构，不要录入真实成员、真实联系方式、真实稿件或真实残疾信息。

在下面任何“隐私与授权”或“备份与安全”项目未通过时，**不得正式上线**。

## 一、启动和自动验收

- [ ] 本地 PostgreSQL 已启动并能正常响应。
- [ ] <http://localhost:3000/api/health> 显示 `{"ok":true}`。
- [ ] 已在项目目录运行 `pnpm verify:acceptance`。
- [ ] Phase 2、3、4、5、6 的虚构数据验收全部通过。
- [ ] Phase 4 验收使用模拟搜索，没有调用 Just One API，也没有产生费用。
- [ ] 验收结束后，后台没有遗留名称中带“验收测试”的虚构记录。

## 二、电脑端页面

- [ ] <http://localhost:3000/> 首页正常打开，导航和栏目说明清楚。
- [ ] <http://localhost:3000/members> 成员页正常打开，空状态或成员卡片显示正常。
- [ ] <http://localhost:3000/works> 作品页正常打开，正文分段和署名正常。
- [ ] <http://localhost:3000/news> 动态页正常打开，来源和原文链接清楚。
- [ ] <http://localhost:3000/submit> 投稿页正常打开，必填项和授权确认清楚。
- [ ] <http://localhost:3000/admin> 后台可以登录，成员、投稿、公开作品、新闻候选和搜索记录均可打开。
- [ ] 页面没有遮挡、无法点击、明显错字或持续报错。

## 三、手机尺寸页面

- [ ] 首页在手机宽度下没有横向滚动条，导航可以使用。
- [ ] 成员、作品和动态页面的文字没有超出屏幕。
- [ ] 投稿表单的输入框、选择项和提交按钮可以正常操作。
- [ ] 长标题、长网址和长段落能够自动换行。
- [ ] 页面放大后仍能阅读和操作。

## 四、成员与授权流程

- [ ] 用一名完全虚构的成员完成新建、保存和修改。
- [ ] 未开启个人主页公开条件时，该成员不会出现在公开成员页。
- [ ] “在册”“公开授权已同意”“允许未来展示个人主页”三项同时满足后才公开。
- [ ] 关闭其中任一项后，成员会从公开页面隐藏，后台记录仍保留。
- [ ] 残疾类别和残疾等级的公开开关互相独立。
- [ ] 未分别取得明确同意的残疾信息不会公开。

## 五、投稿和作品流程

- [ ] 使用虚构姓名、虚构联系方式和虚构正文提交一篇测试稿件。
- [ ] 提交后页面显示投稿编号，未登录访客无法查询稿件或联系方式。
- [ ] 后台可以修改审核状态、填写内部意见并关联虚构成员。
- [ ] 投稿改为“已采用”后不会自动出现在作品页。
- [ ] 只有另建公开作品、确认授权并设为“已发布”后才会公开。
- [ ] 撤回公开授权或改回草稿后，作品立即从公开页面隐藏。

## 六、动态和微信公众号搜索

- [ ] 虚构新闻候选在“待核实”状态下不会公开。
- [ ] 只改为“已确认”、但未开启公开展示时仍不会公开。
- [ ] “已确认”和“允许在公开动态页展示”同时满足后才公开。
- [ ] 关闭公开展示后，动态会从公开页面隐藏。
- [ ] 真实搜索结果不会自动关联成员、自动确认或自动公开。
- [ ] 搜索结果均经过人工打开原文、核对身份和事实后再采用。

## 七、隐私与授权——全部通过才可上线

- [ ] 未登录访客无法读取投稿人姓名、手机号、微信号、稿件正文和审核意见。
- [ ] 未登录访客无法读取成员搜索关键词、已知公众号、内部备注和授权记录。
- [ ] 未登录访客无法读取新闻候选内部编号、来源标识和核实记录。
- [ ] 未登录访客无法读取公开作品的来源投稿、内部授权说明和投稿联系方式。
- [ ] 网站未保存身份证号、残疾人证号码、证件扫描件或授权书扫描件。
- [ ] 所有计划公开的成员资料、作品和残疾信息都有明确的本人授权。
- [ ] 页面和说明中没有真实测试联系方式、临时密码或 Token。

## 八、备份与安全——全部通过才可上线

- [ ] `.env` 和 `.env.docker` 没有提交到 GitHub。
- [ ] 数据库密码、Payload Secret 和第三方 Token 均为独立的长随机值。
- [ ] GitHub 仓库保持私有。
- [ ] 已完成一次数据库备份，并确认备份文件存放在项目目录和 GitHub 之外。
- [ ] 已记录如何恢复数据库和上传图片，且至少做过一次恢复演练。
- [ ] 正式服务器将启用 HTTPS，后台不会通过明文网络访问。
- [ ] 已确定谁负责管理员账号、服务费用、更新、备份和故障处理。

## 九、最终决定

- [ ] 所有发现的问题已经修复并重新验收。
- [ ] 所有隐私与授权项目全部通过。
- [ ] 所有备份与安全项目全部通过。
- [ ] 已确认公开页面的名称、说明和联系方式符合实际运营安排。
- [ ] 项目负责人明确同意进入正式部署阶段。

只有以上项目全部完成，才将结论记录为“本地验收通过，可以进入正式部署”。否则结论应为“继续本地测试，暂不部署”。
