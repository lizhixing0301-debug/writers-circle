# Writers Circle Phase 3 新闻候选库设计

## 目标

Phase 3 为 Writers Circle 增加一套只供管理员使用的“新闻候选库”，用于记录、分类和人工核实与成员有关的公开新闻线索。

本阶段只建设稳定的数据结构、后台审核流程和一个仅供服务器内部代码调用的录入接口。管理员可以在 Payload 后台手工新增候选；未来的公开线索页或自动搜索程序也可以复用同一个内部接口，但本阶段不提供任何公开线索页面、公开写入地址、搜索程序或 AI 功能。

## 已确认的范围

在以下三种方式中，采用第一种，并按用户要求删除公开线索页：

1. 先建设后台新闻候选库和未来录入接口，再在后续阶段接入自动搜索或公开线索。
2. 本阶段直接开发自动搜索；该方案需要提前确定搜索来源、密钥、费用和同名识别规则，范围过大。
3. 只建设 Payload 字段，不提供清楚的内部录入边界；该方案虽然代码更少，但后续采集程序容易绕过统一校验。

本阶段不创建 `/tip`，首页不增加“提供线索”入口，也不收集线索提供人的姓名和联系方式。

## 后台新闻候选库

新增 Payload 集合 `news-candidates`，后台中文名称为“新闻候选”。集合只允许已登录管理员读取、创建、修改和删除。

### 基本信息

- `candidateNumber`：服务器生成且唯一的候选编号，方便编辑沟通和核对。
- `title`：候选标题，必填。
- `relatedMember`：选填，关联已有成员档案。
- `relatedPersonName`：选填，记录来源中出现的姓名；在尚未确认对应成员时使用。
- `category`：新闻类别，必填。
- `summary`：候选摘要或核实要点，选填，只保存必要信息，不复制整篇来源文章。
- `publishedAt`：原来源的发表或事件日期，选填。

新闻类别固定为：

- `creation`：创作动态。
- `award`：获奖荣誉。
- `activity`：活动动态。
- `media`：媒体报道。
- `personal`：个人动态。
- `other`：其他。

### 来源信息

- `sourceType`：来源方式，必填；当前管理员手工新增时默认 `manual`。
- `sourceName`：来源名称，选填，例如媒体、机构或网站名称。
- `sourceUrl`：公开来源链接，选填，只接受 `http` 或 `https` 地址。
- `sourceReference`：外部来源标识，选填；为未来线索或自动采集程序保留，不向公众提供入口。
- `discoveredAt`：候选进入系统的时间，创建时由服务器记录。

`sourceType` 预留以下固定值：

- `manual`：管理员手工录入。
- `publicTip`：未来公开线索入口。
- `automaticSearch`：未来自动搜索程序。

预留值只用于保证以后接入时不需要重建数据库。本阶段只有 `manual` 会通过后台正常使用，不实现另外两种来源的用户界面或网络服务。
后台中的来源方式为只读字段，避免管理员把手工录入误标成尚未开发的来源；未来服务器内部接口仍可明确写入预留值。

### 核实管理

- `status`：核实状态，默认“待核实”。
- `verificationNotes`：仅后台可见的核实记录，选填。
- `verifiedAt`：完成核实的时间，选填，由管理员在确认事实后记录。

核实状态固定为：

- `pending`：待核实。
- `verifying`：核实中。
- `confirmed`：已确认。
- `rejected`：不采用。
- `duplicate`：重复线索。

后台必须醒目说明：“新闻候选未经人工核实不得发布；‘已确认’只表示编辑完成来源核实，不代表已经对外发布。”

Phase 3 不增加“已发布”状态，因为新闻展示、周报和公众号发布都不属于本阶段。

## 未来录入接口

新增一个只存在于服务器 TypeScript 代码中的窄接口，而不是公开 HTTP 地址：

```ts
type NewsCandidateIngestionInput = {
  category: NewsCategory
  relatedMember?: number | string
  relatedPersonName?: string
  sourceName?: string
  sourceReference?: string
  sourceType: NewsSourceType
  sourceUrl?: string
  summary?: string
  title: string
  publishedAt?: string
}
```

接口负责：

1. 只接受白名单字段。
2. 整理首尾空格并校验必填项、长度、类别、来源类型、日期和网址。
3. 创建记录时强制使用“待核实”状态，不允许未来采集程序自行标记“已确认”。
4. 返回候选编号，不返回其他后台记录。
5. 保持存储实现可替换，使未来公开线索页或自动搜索程序无需直接依赖 Payload 字段细节。

本阶段不创建 `/api/public/...` 路由，不存在未登录用户可以调用的新闻候选写入接口。“接口预留”仅表示项目内部已经有稳定、受测试的录入函数。

## 数据流与权限边界

当前手工流程：

1. 管理员登录 `/admin`。
2. 在“新闻候选”中新增标题、类别、来源和摘要。
3. 系统生成候选编号、进入时间和“待核实”状态。
4. 管理员查看原来源、确认相关成员并填写核实记录。
5. 管理员把状态改为“核实中”“已确认”“不采用”或“重复线索”。

未来程序流程只预留到：未来服务器程序调用内部录入函数后，记录仍以“待核实”进入相同后台。任何未来来源都不能绕过人工审核直接进入对外发布流程。

未登录用户不得通过 Payload REST 或 GraphQL 接口读取、创建、修改或删除新闻候选。当前公开页面不得读取候选库。

## 隐私、准确性与安全

- 新闻候选默认全部为后台私有数据。
- 不保存线索提供人的姓名、联系方式、IP 地址或其他身份信息。
- 不在新闻候选中保存残疾类别、残疾等级、身份证号、证件号码或证件图片。
- 如果来源包含敏感信息，摘要只记录完成编辑核实所必需的最少内容，不复制无关隐私。
- 不因来源中出现相同姓名就自动关联成员；成员关联由管理员人工确认。
- 不把“搜索到”“已收录”或“来源看似可靠”当作事实已经核实。
- 来源链接只允许 `http` 和 `https`，拒绝脚本协议和格式错误的网址。
- 摘要保存纯文本，不接受 HTML 或脚本。
- 错误信息和运行日志不得输出 Secret、数据库连接信息或完整候选内容。
- 测试和运行验收只使用完全虚构的人名、来源和新闻内容，验收后清理数据库。

## 后台可维护性

- 继续使用 Payload 自带列表和编辑界面，不制作自定义新闻工作台。
- 列表默认显示候选编号、标题、关联成员、类别、核实状态和发现时间。
- 默认按发现时间倒序排列。
- 字段名称和中文说明保持清楚，使非程序员管理员能够直接使用。
- 不增加新的数据库、消息队列、定时任务、搜索服务或外部依赖。

## 错误处理

- 标题或类别缺失时拒绝保存，并显示明确中文提示。
- 类别、来源类型或状态不在固定列表中时拒绝保存。
- 链接不是有效的 `http` 或 `https` 地址时拒绝保存。
- 日期无效或字段超过长度限制时拒绝保存。
- 内部录入接口收到额外字段时拒绝处理，避免未来程序意外写入核实状态或内部备注。
- 数据库写入失败时不得伪造候选编号或成功结果。
- 关联成员不存在时由 Payload 拒绝保存，不得自动新建成员。

## 测试与验收

自动化和运行时验收至少覆盖：

- 新闻候选集合已经注册，后台中文名称、默认列表、分类和状态符合设计。
- 未登录用户不能通过 Payload 接口读取、创建、修改或删除候选。
- 创建记录时由服务器生成唯一编号和进入时间，并强制默认“待核实”。
- 管理员后续更新时可以保留核实状态、核实记录和成员关联。
- 内部录入接口只接受白名单字段，不能写入候选编号、核实状态、核实记录或确认时间。
- 标题、类别、来源类型、日期、长度和网址校验生效。
- 内部录入成功只返回候选编号；数据库异常时不伪造成功。
- 使用虚构候选完成一次实际创建、关联成员、更新核实状态、未登录权限检查和自动清理。
- 首页、投稿页和 Payload 后台继续正常打开。
- 单元测试、代码检查、Payload 类型生成和生产构建全部通过。

## 本阶段明确不做

- `/tip` 或任何“提供线索”公开页面。
- 公众线索提交、线索人姓名、联系方式或公开回执。
- 自动网络搜索、网页抓取、RSS、搜索引擎或第三方采集工具。
- AI 人物判断、事实核验、摘要、改写、分类或去重。
- 自动关联成员或根据残疾信息筛选新闻。
- 新闻公开列表、新闻详情页、成员动态展示或网站搜索。
- 周报、编辑排版、微信公众号草稿或自动发布。
- 邮件、短信、微信或其他自动通知。
- Docker Compose、正式域名、服务器或线上部署。

## 完成条件

Phase 3 只有在以下条件全部满足后才能完成：

- 管理员可以在 `/admin` 使用“新闻候选”完成手工录入和人工核实管理。
- 内部录入接口已经具备明确类型、输入校验和自动化测试，但没有公开 HTTP 入口。
- 新闻候选、来源信息、成员关联和核实记录均保持后台私有。
- 虚构候选完成一次实际录入、核实和清理流程。
- 测试、代码检查、Payload 类型生成和生产构建通过。
- 首页、投稿页和后台通过实际 HTTP 检查。
- 没有真实新闻、真实成员隐私、密码、Secret 或数据库文件进入 Git。
- 主要使用方法写入中文文档。

完成后停止，不进入自动新闻搜索、公众线索、AI、公开展示、微信公众号接入或其他后续阶段。
