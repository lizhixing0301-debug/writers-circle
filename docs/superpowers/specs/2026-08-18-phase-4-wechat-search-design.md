# Writers Circle Phase 4 全微信公众号搜索设计

## 目标

Phase 4 使用成员档案中的姓名、笔名、其他署名和搜索关键词，在第三方服务覆盖的整个微信公众号文章索引中查找近期相关文章，并把结果作为“待核实”的新闻候选保存到现有后台。

搜索范围不限定管理员事先关注或登记的公众号，但也不承诺收录微信中的每一篇文章。第三方搜索结果只是一条线索，不能代替编辑核实。

## 已确认的技术路线

微信官方接口不提供服务器端的“搜索全部公众号文章”能力。本阶段采用可替换的 `WechatArticleSearchProvider` 接口，首个实现接入 Just One API 的微信公众号文章搜索服务。

选择第三方 API 而不直接模拟微信或搜狗浏览器操作，原因是：

- 不需要在 Writers Circle 中保存个人微信登录状态、Cookie 或扫码会话。
- 不需要安装反指纹浏览器或处理验证码。
- 能设置明确的调用数量上限，便于控制费用。
- 服务发生变化时只替换适配器，不影响成员、新闻候选和人工核实流程。

API Token 只从服务器环境变量读取，不写入代码、数据库、运行记录或 GitHub。第三方服务可能收费、限流、超时或停止服务；这些情况必须被视为可恢复的外部故障，不能影响后台其他功能。

## 搜索范围与关键词

只搜索状态为“在册”的成员。每名成员的搜索词按以下顺序生成：

1. 姓名。
2. 笔名。
3. 其他署名。
4. 管理员填写的搜索关键词。

搜索词会去除空白和重复值。每次运行最多调用 64 个搜索词，每个搜索词只取第一页、优先最近七天并按最新结果排序。这样可以保证32名成员的姓名优先得到搜索，同时给部分成员保留笔名或补充关键词的位置，并避免一次点击产生无法控制的调用费用。

本阶段不使用残疾类别、残疾等级、公开授权状态、联系方式或内部备注生成搜索词。

## 第三方搜索适配器

新增接口：

```ts
type WechatArticleSearchProvider = {
  search(query: string): Promise<WechatArticleSearchItem[]>
}
```

首个实现通过 HTTPS 调用 Just One API 的文章搜索 V1 接口，固定使用：

- `publishTimeType=SEVEN_DAYS`
- `sortType=LATEST`
- `currentPage=1`
- `offset=0`
- 空的 `cookies_buffer`

每次请求最多等待 60 秒。HTTP 错误、无效 JSON、非零业务状态码、缺失 Token、余额不足、调用上限、限流和无法识别的返回结构都转换成不包含 Token 的中文错误。

第三方返回格式可能变化，因此解析器只接受能够识别出标题和公开微信公众号文章网址的记录，并兼容常见的字段名称。不能安全识别的条目会被忽略，不会把不完整或非微信链接写入数据库。

## 新闻候选写入

每条有效结果只保存：

- 标题。
- 公众号名称。
- 微信公开文章链接。
- 发布时间（如果服务提供）。
- 简短摘要（如果服务提供，清除 HTML 并限制长度）。
- 命中的成员搜索词，放入“来源中出现的姓名”。
- 稳定的外部来源标识，用于防重复。

写入现有 `news-candidates` 集合时固定使用：

- `sourceType = automaticSearch`
- `category = other`
- `status = pending`

系统不会因为姓名相同而自动设置 `relatedMember`。管理员必须打开原文核对身份后再关联成员和选择正确类别。

同一篇微信文章会根据规范化后的文章身份生成稳定引用。数据库中已经存在该引用时，本次运行记为“重复”，不会新增候选。程序不读取评论、阅读者信息、整篇正文、图片或其他私人数据。

## 搜索运行记录

新增私有 Payload 集合 `wechat-search-runs`，后台名称为“公众号搜索记录”。只允许已登录管理员查看和删除；运行状态和统计只能由服务器程序写入。

每条运行记录包含：

- 搜索编号。
- 触发方式（后台按钮或验收脚本）。
- 状态：排队中、运行中、成功、部分成功、失败。
- 开始和完成时间。
- 成员数量、计划搜索词数量和实际 API 调用次数。
- 返回结果数、新增候选数、重复数、失败搜索词数。
- 不含 Token、成员隐私和完整第三方响应的中文错误摘要。

某一个搜索词失败时继续处理其他搜索词；有成功也有失败时记录为“部分成功”。全部失败或缺少 Token 时记录为“失败”。

## 后台操作

在“新闻候选”列表上方增加“立即搜索全部成员”按钮和简短说明。按钮调用只允许已登录管理员访问的内部路由。

点击后：

1. 如果已有任务正在运行，返回现有运行编号，不再重复启动。
2. 否则创建一条排队记录并在服务器后台开始执行。
3. 页面立即显示运行编号，并提示管理员稍后查看“公众号搜索记录”。

搜索任务在 Node.js 进程后台运行，不阻塞浏览器。Phase 4 不增加每日定时任务；正式 Docker 部署时可以直接调用同一个运行函数接入计划任务。

## 权限、安全与费用控制

- 启动路由必须通过 Payload 登录身份验证；未登录请求返回 401。
- API Token 使用 `WECHAT_SEARCH_API_TOKEN` 环境变量，并在 `.env.example` 中只放无效占位说明。
- API 地址默认固定为 `https://api.justoneapi.com`；可替换地址仍只允许 HTTPS。
- 单次运行最多 64 次外部调用，每个词只查一页，不自动重试。
- 错误日志不输出 Token、完整环境变量、完整第三方响应或成员敏感资料。
- 不访问普通网站、RSS、新闻搜索引擎、朋友圈或其他社交平台。
- 不接入 AI，不自动判断身份、类别或事实真假。
- 不自动发布网站、公众号草稿或公众号文章。

## 测试与验收

自动化测试使用完全虚构的成员、公众号和文章，外部 API 由受控的虚构响应替代，不消耗费用。

至少覆盖：

- 搜索词优先级、去重和 64 次上限。
- Token 不进入请求网址、错误信息或运行记录。
- API 表单参数、超时、HTTP 错误、业务错误和响应解析。
- 只接受微信公众号文章网址并清除摘要 HTML。
- 微信文章身份规范化和重复判断。
- 运行记录的权限、只读字段和服务器状态更新。
- 全成功、部分成功、全部失败、无成员、缺少 Token和重复文章。
- 未登录用户不能启动搜索或读取搜索记录。
- 使用真实 PostgreSQL、虚构提供者完成一次搜索、候选创建、重复跳过、统计核对和自动清理。
- 首页、投稿页、后台、单元测试、代码检查、类型生成和生产构建继续通过。

如果没有配置真实 Token，只能证明本项目的搜索流程、数据库写入和第三方接口契约正确，不能声称真实第三方搜索已经联通。真实联网验收必须在用户取得试用 Token 后单独执行。

## 本阶段明确不做

- 监控固定公众号、RSS 或普通网站。
- 搜索朋友圈、视频号、微信群或私人聊天。
- 复制、下载或对外展示整篇公众号文章。
- AI 摘要、AI 分类、AI身份判断或 AI 核实。
- 自动关联成员、自动确认、自动发布或自动发送公众号。
- 每日定时任务、Docker Compose、服务器和线上部署。
- 充值、购买套餐或代表用户接受第三方付费协议。

## 完成条件

- 管理员能从新闻候选后台启动一次全成员微信公众号文章搜索。
- 搜索使用成员公开检索字段，具备固定调用上限和可替换提供者。
- 搜索结果只能以待核实候选进入后台，并且不会自动关联成员。
- 搜索记录能说明调用、结果、新增、重复和错误数量。
- 没有 Token 时给出清楚错误，项目其他页面仍正常。
- 虚构提供者的完整 PostgreSQL 验收、测试、代码检查、类型生成和生产构建全部通过。
- 没有密码、Token、真实新闻、真实成员隐私或数据库文件进入 Git。

完成后停止，不进入定时任务、AI、新闻展示、公众号草稿或发布等后续阶段。
