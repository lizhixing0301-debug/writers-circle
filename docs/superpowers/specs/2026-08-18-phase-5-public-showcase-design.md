# Writers Circle Phase 5 公开展示设计

## 目标

为“三十二人文学志”提供一个可由非程序员在 Payload 后台维护的公开展示网站：成员列表、成员详情和已人工确认且允许公开的文学动态。

## 已确认规则

- 继续使用现有 Next.js、Payload CMS、PostgreSQL 单体结构，不增加第三方服务或费用。
- 公开页面只通过单独的“安全公开数据层”读取 Payload；不得直接将成员或新闻候选原始记录传入页面。
- 成员须同时满足：`status=active`、`consentStatus=granted`、`publicProfileEnabled=true`，才进入公开成员列表或详情。
- 公开成员信息限定为姓名、笔名、头像及替代文字、地区、文学身份、所属机构、公开简介、代表作品、个人公开主页；不输出其他署名、搜索词、已知公众号、完整后台简介、内部备注或授权记录。
- 残疾类别与等级默认隐藏。只有成员已同意、个人主页已开启，且对应的独立公开开关开启时，才分别显示；两个字段互不连带。
- 新闻候选必须先由管理员人工设为“已确认”，再主动开启“允许公开”，才会出现在公开动态页。
- 公开动态只显示标题、类别、日期、来源名称、简短摘要、公开来源链接及关联的已公开成员；核实记录、候选编号、来源标识、搜索词和内部信息永不公开。
- 不做新闻详情页；来源文章继续在原公众号页面打开。
- 不做 AI、公众号草稿/发布、自动搜索、定时任务、公众线索、Docker 或部署。

## 页面

- `/`：项目介绍、成员展示入口、动态入口、投稿入口；管理后台仍可访问但不作为公众主入口。
- `/members`：按后台展示顺序显示公开成员。
- `/members/[slug]`：公开成员的文学资料与代表作品；未获公开授权或不存在时返回 404。
- `/news`：按事件/发表日期倒序显示允许公开的已确认动态，并链接至原始公开来源。

## 后台维护方式

管理员只需在 Payload 后台完成：

1. 为成员记录“已同意”并开启“允许展示个人主页”；如确实得到单独同意，再开启残疾类别或等级的对应开关。
2. 将新闻候选人工核实为“已确认”，检查标题、日期、摘要和来源链接后，开启“允许公开”。

关闭任何一个条件后，下一次访问公开页面时该内容即不再显示。

## 验收与安全

- 单元测试证明未授权成员、后台私密字段、未确认新闻和未开启公开的新闻均不能进入公开数据。
- 页面测试证明成员列表、成员详情、动态列表和首页入口存在，且未泄露内部字段。
- 运行时验收使用完全虚构数据，完成后清理。
- 全量测试、代码检查、Payload 类型生成、生产构建和本地 HTTP 检查均通过后才提交并推送 GitHub 私有仓库。
