# Writers Circle Phase 6 公开作品设计

## 目标

为“三十二人文学志”增加由管理员人工维护的公开作品栏目，让读者可以浏览已经审核、已经确认公开授权的文学作品。

## 核心原则

- 投稿审核与公开发布严格分开。“已采用”的投稿不会自动公开。
- 新建独立的“公开作品”后台栏目，管理员人工核对标题、署名、分类、正文和授权后发布。
- 只有同时满足“状态为已发布”和“已确认公开授权”的作品才会进入公开页面。
- 投稿人的真实姓名、联系方式、投稿编号、补充说明和内部审核意见永远不得进入公开数据。
- 作品正文保存为纯文本并按自然段展示，不接受或渲染 HTML、脚本和嵌入代码。
- 不调用 Just One API，不使用 AI，不连接微信公众号，不增加外部服务或费用。

## 后台数据结构

新增 Payload 集合 `published-works`，后台中文名称为“公开作品”。

字段包括：

- `title`：公开标题，必填。
- `slug`：作品网址标识，必填且唯一，只使用小写字母、数字和短横线。
- `authorName`：公开署名，必填。该字段由管理员根据作者授权填写，不自动复制投稿人真实姓名。
- `relatedMember`：可选关联成员。仅用于建立公开成员页面链接；成员本身未获公开授权时只显示作品署名，不生成成员链接。
- `category`：诗歌、小说、散文、评论或其他。
- `excerpt`：作品列表使用的简短导语，选填，最多 500 字。
- `content`：公开正文，纯文本，必填，20 至 100000 字符。
- `sourceSubmission`：可选关联原投稿，仅供后台追溯，不进入公开数据。
- `publicationAuthorized`：已确认作者同意在网站公开，默认关闭。
- `authorizationNotes`：授权范围或核对说明，仅后台可见。
- `status`：草稿、已发布、已归档，默认草稿。
- `publishedAt`：首次正式发布时间。作品首次从草稿变为已发布时由服务器填写；归档后保留。

## 发布保护

- 未开启 `publicationAuthorized` 时，系统自动把作品保持为草稿，不能处于已发布状态。
- 撤销公开授权时，系统自动把已发布作品改回草稿，但不删除正文。
- 管理员不能通过新建记录直接伪造发布时间；首次发布时间由服务器生成。
- 网址标识格式不正确或重复时拒绝保存。

## 公开数据与页面

在现有安全公开数据层增加白名单映射，仅输出：标题、网址标识、公开署名、类别、导语、正文、发布时间，以及可选的已公开成员链接。

新增页面：

- `/works`：按发布时间倒序显示已发布作品。
- `/works/[slug]`：显示单篇作品正文；草稿、归档、未授权或不存在的作品返回 404。
- 首页新增“文学作品”入口。

作品详情页不显示投稿来源、投稿编号、联系方式、授权备注或后台状态。正文以普通 React 文本节点渲染，按空行分段，不使用 `dangerouslySetInnerHTML`。

## 非本阶段范围

- 投稿自动转作品、批量发布或定时发布。
- 富文本编辑器、Word/PDF 导入、附件、音频或视频。
- 点赞、评论、收藏、阅读量、账号或搜索。
- AI 校对、摘要、排版或分类。
- 微信公众号草稿、发布或同步。
- Docker Compose、服务器部署和正式域名。

## 验收

- 单元测试覆盖默认草稿、授权撤销、发布时间、网址格式和后台权限。
- 安全公开数据测试证明草稿、未授权作品和所有后台字段无法进入公开结果。
- 页面测试覆盖作品列表、详情、404、纯文本安全渲染和首页入口。
- 运行验收使用完全虚构作品，验证公开与隐藏条件及本地 HTTP 页面，最后清理虚构数据。
- 全量测试、代码检查、Payload 类型生成和生产构建通过后，合并到 `main` 并推送私有 GitHub。
