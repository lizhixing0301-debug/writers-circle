# Phase 8 本地验收与上线准备设计

## 目标

在不增加业务功能、不公开部署网站的前提下，用虚构数据完整检查 Writers Circle 第一版的主要流程、公开页面、隐私边界和日常操作说明，形成可以由非程序员重复使用的本地验收方法。

## 范围

Phase 8 包含：

- 把现有 Phase 2 至 Phase 6 的虚构数据验收整合成一个简单命令；
- 检查首页、成员、作品、动态、投稿和 Payload 后台在电脑与手机尺寸下能否正常访问和使用；
- 重新检查未登录访客不能读取投稿联系方式、内部备注、授权记录、残疾信息等私密字段；
- 编写面向非程序员的日常使用说明和正式上线检查清单；
- 修复验收中发现的明确缺陷，但不改变已经批准的业务规则。

Phase 8 不包含：

- 正式服务器、域名、HTTPS 或互联网发布；
- AI、微信公众号自动发布、定时搜索或公众线索入口；
- 新增栏目、账号体系、通知、附件上传或其他新业务功能；
- 录入真实成员、真实投稿或真实残疾信息。

## 验收方式

### 自动验收

新增 `pnpm verify:acceptance` 命令。命令先确认本地网站健康接口可用，再依次运行现有的 Phase 2、3、4、5、6 虚构数据验收脚本。每个脚本负责建立虚构记录、检查流程和权限，并在结束时删除测试记录。

如果网站尚未启动，命令用中文说明应先启动数据库和网站；如果任一步失败，立即停止并保留清楚的失败阶段，不继续制造更多测试数据。

### 页面验收

通过本地浏览器检查以下地址：

- `/` 首页；
- `/members` 成员展示；
- `/works` 文学作品；
- `/news` 文学动态；
- `/submit` 公开投稿；
- `/admin` Payload 后台；
- `/api/health` 健康接口。

公开页面分别用常见电脑尺寸和手机尺寸检查。重点关注导航、标题、表单、空状态、正文换行、按钮可点击性以及页面横向溢出。

### 人工验收

提供一份逐项勾选清单。用户只需按清单打开页面、使用虚构内容操作，并记录“通过”或“需要修改”。清单特别提醒：真实信息只有在隐私边界、授权和备份全部确认后才可录入。

## 隐私和数据安全

- 自动验收只使用名称中明确含有“验收测试”的虚构数据；
- Phase 4 验收继续使用模拟搜索结果，不调用 Just One API，不产生费用；
- 验收过程中不保存真实姓名、联系方式、残疾类别、残疾等级、证件信息或真实稿件；
- 自动脚本沿用现有清理逻辑，完成后删除其创建的虚构数据；
- `.env`、Token、数据库密码和 Payload Secret 继续只保存在 Git 忽略文件中。

## 文档交付

创建两份中文文档：

1. `docs/operations/daily-use-guide.md`：管理员日常登录、录入、审核、发布、撤回和搜索的简明说明；
2. `docs/acceptance/pre-launch-checklist.md`：上线前逐页、逐流程、逐项隐私核对表。

README 只增加简短入口，避免把首页说明写得过长。

## 成功标准

- `pnpm verify:acceptance` 可以在网站运行时完成全部五组虚构数据验收；
- 公开页面和后台在浏览器中均能打开，健康接口返回成功；
- 电脑和手机尺寸下无阻止使用的布局问题；
- 完整单元测试、代码检查、类型生成和生产构建通过；
- 日常使用说明和上线检查清单可以由没有编程经验的用户直接照着操作；
- Phase 8 的提交中没有真实数据、密码、Secret 或 Token。
