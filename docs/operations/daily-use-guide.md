# Writers Circle 日常使用说明

这份说明面向不懂编程的管理员。日常内容管理都在浏览器完成，不需要修改代码。

## 一、打开和登录

1. 确认本地数据库和 Writers Circle 已经启动。
2. 打开 <http://localhost:3000/admin>。
3. 输入你自己设置的管理员邮箱和密码。
4. 如果这是第一次使用，而且页面提示尚无管理员，打开 <http://localhost:3000/admin/create-first-user> 创建第一个管理员。

管理员密码只应由管理员本人保存，不要写进项目文件、聊天记录或 GitHub。

## 二、理解三个不同动作

- **保存后台记录**：资料只保存在管理后台，不等于对外公开。
- **允许公开展示**：表示已经取得当事人同意，但仍要满足相应栏目规则。
- **发布**：让符合公开条件的内容出现在网站公开页面。

只要对授权范围拿不准，就先保存为后台记录，不要开启公开开关或发布状态。

## 三、录入成员档案

1. 在后台打开“成员档案”，新建成员。
2. 填写姓名、笔名、文学身份、简介和代表作品等资料。
3. 搜索关键词和已知公众号只用于后台搜索，不会公开。
4. 在授权信息中记录你何时、通过什么方式征求过成员意见。
5. 只有成员已经明确同意时，才开启“允许未来展示个人主页”。
6. 成员要出现在公开页面，还必须同时处于“在册”状态，并且公开授权状态为“已同意”。

残疾类别和残疾等级是两项独立的敏感信息。即使成员同意公开个人主页，也不会自动公开这两项。只有成员分别明确同意后，才能开启相应的公开开关。

不要录入身份证号、残疾人证号码、证件照片、授权书扫描件或与文学展示无关的敏感信息。

## 四、处理投稿

1. 投稿人通过 <http://localhost:3000/submit> 提交纯文字作品。
2. 在后台打开“投稿管理”查看新稿件。
3. 根据实际进度修改为“待审核”“审核中”“退回修改”“已采用”或“不采用”。
4. 审核意见只写必要内容，不要复制或扩散投稿人的联系方式。
5. 需要联系投稿人时，由管理员通过其留下的联系方式人工沟通。

“已采用”不等于“已经公开”。投稿内容要公开，仍需在“公开作品”中另行建立记录并再次核对授权。

## 五、发布或撤回公开作品

1. 在后台打开“公开作品”，新建记录。
2. 填写公开标题、网址标识、公开署名、类别、导语和正文。
3. 如作品来自投稿，可关联“来源投稿”；该关联不会公开。
4. 核对作者同意公开的署名和正文，在授权说明中记录核对情况。
5. 开启“已确认作者同意在网站公开”。
6. 把发布状态改为“已发布”，保存后到 <http://localhost:3000/works> 检查。

如果作者撤回授权，关闭公开授权或把状态改回草稿。作品会从公开页面隐藏，但后台记录不会被删除，便于保留必要的工作记录。

## 六、核实和发布文学动态

1. 在后台打开“新闻候选”。
2. 打开候选原文，人工核对人物身份、日期、事实和来源。
3. 只有确认是同一位成员后，才关联成员档案。
4. 摘要只写必要事实，不复制整篇文章，也不写无关隐私。
5. 把状态改为“已确认”，并在确实适合公开时开启“允许在公开动态页展示”。
6. 到 <http://localhost:3000/news> 检查公开结果。

“已确认”只表示完成编辑核实；只有同时开启公开展示，内容才会出现在公开页面。

## 七、搜索微信公众号文章

1. 在“新闻候选”列表上方点击“立即搜索全部成员”。
2. 等待搜索完成，查看“公众号搜索记录”中的新增、重复和错误数量。
3. 搜索结果固定进入“待核实”，不会自动关联成员，也不会自动公开。
4. 逐条打开原文进行人工核实，再决定是否采用。

搜索会使用第三方服务并可能产生费用。系统不会自动充值，也不能保证收录微信中的全部文章。

## 八、每天结束前

1. 打开首页、成员页、作品页和动态页，检查当天公开内容。
2. 确认没有把联系方式、内部备注、授权记录或不应公开的残疾信息显示出来。
3. 本机开发模式下，可在运行窗口按 `Control + C` 停止网站。
4. 使用 Docker Compose 时，执行 `pnpm docker:down` 只停止服务，不删除数据库和图片。

不要删除数据库目录、Docker 数据卷或 `.env` 文件。需要迁移电脑、恢复数据或正式上线时，先做备份并由技术人员操作。

## 九、遇到问题时

- 页面打不开：先确认数据库和网站是否都已启动。
- 搜索失败：先看后台搜索记录中的说明，不要反复连续点击，以免重复产生费用。
- 公开内容不见了：检查状态、公开授权和栏目公开开关是否同时满足。
- 不确定是否可以公开：先保持后台私有，取得明确同意后再操作。

上线前请逐项完成[《正式上线前检查清单》](../acceptance/pre-launch-checklist.md)。
