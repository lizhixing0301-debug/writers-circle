# Writers Circle（三十二人文学志后台）

这是 Writers Circle（三十二人文学志后台）的本地开发项目，使用 Next.js、Payload CMS 与 PostgreSQL。

当前已包含成员档案后台、公开成员展示、公开文学动态、公开投稿、新闻候选库和 Phase 4 全微信公众号文章搜索入口。公众线索入口、AI 和自动发布尚未开发。

## 本地地址

- 首页：<http://localhost:3000>
- 成员展示：<http://localhost:3000/members>
- 文学动态：<http://localhost:3000/news>
- 投稿页：<http://localhost:3000/submit>
- Payload 后台：<http://localhost:3000/admin>
- 首次创建管理员：<http://localhost:3000/admin/create-first-user>

项目不会预设管理员邮箱或密码。第一次使用后台时，请在 Payload 页面自行创建管理员。

## 成员档案

登录 Payload 后台后，可以在“内容管理”中看到：

- “成员档案”：录入姓名、笔名、文学资料、作品、搜索关键词和授权情况。
- “图片资源”：上传成员头像，并填写方便读屏软件理解的图片说明。

成员资料默认不会公开。成员要出现在 <http://localhost:3000/members>，必须同时满足：成员状态为“在册”、公开授权状态为“已同意”，并开启“允许未来展示个人主页”。关闭其中任一项后，成员会从公开页面隐藏。

公开页面只展示姓名、笔名、头像、地区、文学身份、所属机构、公开简介、代表作品和个人公开主页。完整简介、搜索关键词、已知公众号、内部备注和授权记录永远不会公开。

残疾类别与残疾等级默认隐藏，并且互相独立。只有已取得该成员明确同意后，才可以在“残疾信息”中开启对应的“允许未来公开”开关；未开启的字段绝不会因为个人主页公开而自动显示。

请勿在项目中保存身份证号、残疾人证号码、证件扫描件、授权书扫描件或其他不必要的敏感材料。

## 公开投稿

投稿人打开 <http://localhost:3000/submit> 后，无需注册或登录，可以填写：

- 投稿人姓名；
- 笔名（选填）；
- 手机号或微信号；
- 文章标题和作品类别；
- 粘贴的文章正文；
- 补充说明（选填）；
- 原创或投稿授权确认。

提交成功后，页面会显示一个投稿编号。稿件和联系方式不会公开，也不能由未登录用户查询。

Phase 2 只接收粘贴的纯文字，不接收 Word、PDF、图片或其他附件。请勿把真实投稿内容、联系方式或导出的数据库文件加入 Git。

## 投稿管理

管理员登录 <http://localhost:3000/admin> 后，可以在“内容管理”中打开“投稿管理”，完成：

- 查看稿件；
- 将稿件关联到已有成员档案；
- 把状态改为“待审核”“审核中”“退回修改”“已采用”或“不采用”；
- 填写仅后台可见的内部审核意见。

公开投稿人不能设置审核状态、成员关联或审核意见。管理员需要退回修改时，应通过投稿人留下的联系方式人工联系。

投稿系统本身仍没有投稿账号、进度查询、附件上传、短信或邮件通知、AI 处理、公开作品页面或自动发布；Phase 4 的微信公众号搜索与投稿流程相互独立。

## 新闻候选管理

管理员登录 <http://localhost:3000/admin> 后，可以在“内容管理”中打开“新闻候选”，完成：

- 手工记录候选标题、新闻类别和来源；
- 将候选关联到已经核对身份的成员档案；
- 填写仅后台可见的核实记录；
- 把状态改为“待核实”“核实中”“已确认”“不采用”或“重复线索”。
- 在确认来源、摘要和关联成员均适合公开后，开启“允许在公开动态页展示”。

**新闻候选必须经过人工核实后才能使用。“已确认”只表示编辑完成来源核实，不代表已经对外发布；只有“已确认”且开启“允许在公开动态页展示”的记录才会出现在 <http://localhost:3000/news>。**

新闻候选、来源信息、成员关联和核实记录全部保持后台私有。不要因为来源中出现相同姓名就直接关联成员，也不要在候选摘要中复制整篇来源文章、残疾类别及等级、证件信息或其他无关隐私。

公开动态只显示标题、类别、日期、来源名称、简短摘要、公开原文链接和关联的已公开成员。候选编号、来源标识、核实记录和其他内部资料不会公开。项目的服务器内部录入接口由 Phase 4 微信公众号搜索复用。当前仍没有 `/tip` 页面、公众线索提交、AI判断、周报或公众号发布功能。

## 全微信公众号文章搜索

管理员可以在“新闻候选”列表上方点击“立即搜索全部成员”。系统会使用所有在册成员的姓名、笔名、其他署名和明确填写的搜索关键词，在第三方服务覆盖的整个微信公众号文章索引中查找最近七天的结果，而不是只搜索已经关注或登记的公众号。

每次运行最多使用 64 个搜索词，每个搜索词只查询一页并优先最新结果。这个上限用于控制第三方服务调用量；实际价格和 Token 预算仍以服务商后台为准，项目不会自动充值。

搜索到的内容只保存标题、公众号名称、发表时间、公开文章链接、简短摘要和命中的搜索词。系统不会抓取整篇正文、评论、读者、图片、朋友圈、视频号或私人信息。

所有搜索结果固定进入“待核实”，默认类别为“其他”，并且不会自动关联成员。管理员必须打开原文确认身份、事实和类别后才能使用。“搜索到”不等于“事实已核实”，第三方搜索也不能保证收录微信中的每一篇文章。

每次搜索都会在“公众号搜索记录”中保存调用数、结果数、新增数、重复数和错误数量。某个搜索词失败时，其他成员仍会继续搜索；第三方服务不可用也不会影响成员、投稿或新闻候选后台。

Phase 4 只提供后台一键运行，不包含每日定时任务。正式 Docker 部署后可以复用同一运行接口增加计划任务。

### 配置搜索服务

全微信公众号搜索使用可替换的第三方接口，当前适配 Just One API。需要先由项目所有人注册服务商账号、查看价格和条款，并取得试用或正式 Token。未经项目所有人同意，本项目不会购买套餐或充值。

把 Token 只写入被 Git 忽略的本机 `.env`：

```text
WECHAT_SEARCH_API_BASE_URL=https://api.justoneapi.com
WECHAT_SEARCH_API_TOKEN=你的服务商Token
```

不要把真实 Token 写进 `.env.example`、源代码、截图、聊天记录或 GitHub。没有配置 Token 时，后台仍能正常打开；点击搜索只会建立一条清楚标注“未配置 Token”的失败记录，不会发送外部请求。

## 环境要求

- Node.js 20.9.0 或更高版本
- pnpm 11
- PostgreSQL（当前 Mac 已安装 Postgres.app 2.9.6，内含 PostgreSQL 18.6）

真实数据库连接信息和 Payload Secret 只保存在被 Git 忽略的 `.env` 中。仓库里的 `.env.example` 只有无效示例值。

## 第一次设置

安装项目依赖并生成本地环境文件：

```bash
pnpm install
pnpm setup:env
```

当前项目使用专用的本地 PostgreSQL 数据目录 `.postgres/data`。如果该目录不存在，可以执行：

```bash
mkdir -p .postgres
/Applications/Postgres.app/Contents/Versions/latest/bin/initdb \
  -D .postgres/data \
  --auth=trust \
  --username="$USER" \
  --encoding=UTF8 \
  --locale=C
```

这个数据库只用于本机开发，并且只监听本机地址。

## 启动

先启动 PostgreSQL：

```bash
/Applications/Postgres.app/Contents/Versions/latest/bin/pg_ctl \
  -D .postgres/data \
  -l .postgres/postgres.log \
  -o "-h 127.0.0.1 -p 5432" \
  start
```

首次启动数据库后，创建项目数据库：

```bash
/Applications/Postgres.app/Contents/Versions/latest/bin/createdb \
  -h 127.0.0.1 \
  -p 5432 \
  -U "$USER" \
  writers_circle
```

再启动 Writers Circle：

```bash
pnpm dev
```

## 检查命令

```bash
pnpm test --run
pnpm lint
pnpm generate:types
pnpm build
```

项目运行后，可以使用一组完全虚构的数据检查完整投稿流程：

```bash
pnpm payload run scripts/verify-phase-2.ts
```

该检查会实际投稿、验证防重复、修改审核状态、关联一名虚构成员、检查未登录隐私权限，最后自动删除虚构稿件和虚构成员。

使用完全虚构的数据检查新闻候选录入和核实流程：

```bash
pnpm payload run scripts/verify-phase-3.ts
```

该检查会通过服务器内部接口建立一条待核实候选，关联一名虚构成员，检查未登录隐私权限和三个本地页面，最后自动删除虚构候选和虚构成员。

使用完全虚构的数据检查全微信公众号搜索流程：

```bash
pnpm payload run scripts/verify-phase-4.ts
```

该检查不会连接第三方服务或产生费用。它会使用虚构搜索结果完成成员关键词生成、候选创建、重复跳过、运行记录、未登录权限和三个本地页面检查，最后自动删除全部虚构数据。

只有配置真实第三方 Token 并完成一次联网搜索后，才能说明第三方服务已经真实联通。单元测试和上述虚构验收不能代替真实联网验收。

使用完全虚构的数据检查公开展示和隐私控制：

```bash
pnpm payload run scripts/verify-phase-5.ts
```

该检查不会调用第三方服务或产生费用。它会创建一名虚构成员和两条虚构动态，验证成员授权、残疾信息独立公开开关、动态公开开关、私密字段隔离及五个本地页面，最后自动删除全部虚构数据。

## 停止 PostgreSQL

```bash
/Applications/Postgres.app/Contents/Versions/latest/bin/pg_ctl \
  -D .postgres/data \
  stop
```
